# Wait What Bro

Comprehension failed. Back up and re-pitch *that* — decide yourself how far back to go, because what lost the user is usually bigger than the last paragraph.

1. Open with just enough context to place the subject and the current state of the work.
2. Reply in the language of the user's last message. Keep commands, code, paths, and names as exact literals.
3. Plain words, active voice, short concrete sentences. No analogies. No jargon, acronyms, or invented terms without a plain definition right where they appear. No filler and no performed slang.
4. Structure the answer around three things: what happened or where the work stands, what it means for the user, what step or decision comes next.
5. Shorter than the original answer, without losing constraints, risks, or verified facts. Talk like one person to another — no condescension.
6. Use only the context already in the conversation. No tool calls, no file reads, no invented facts, no continuing the original work unless separately asked. If something important is missing, say so.

Done when the answer reads clearly on the first pass, contains no undefined terms, and is written in the user's language.
