# Движок кампании: ручной контур, /goal, канбан --goal

Три способа гнать граф тикетов без постоянного «продолжай» от пользователя. Проверено на живой кампании 2026-08-22 (спека #60, тикеты #61–#69, репо с gh-трекером).

## Что есть что

| Движок | Кто запускает | Где живёт луп | Коммиты |
|---|---|---|---|
| Ручной контур | оркестратор в чате | сессия оркестратора | снаружи, по слову владельца |
| `/goal <текст>` | только пользователь | та же сессия, судья после каждого хода | снаружи |
| `hermes kanban create --goal --goal-max-turns <n>` | диспетчер | воркер одной карты | снаружи |

## /goal: проверенные факты

- Ставится слэш-командой в чате (работает на всех gateway-платформах, включая Telegram). **Программной ручки у агента нет**: в тулсете её нет, `hermes goal` в CLI отсутствует — не искать, не выдумывать обход.
- Механика (ралф-луп): после каждого хода лёгкая судейская модель решает «готово/не готово» по последнему ответу; не готово — автопродолжение в той же сессии.
- Бюджет ходов конечный (дефолт ~20); на исходе — «⏸ Goal paused — N/20». Пользователь продолжает через `/goal resume` (счётчик обнуляется), пауза — `/goal pause`, снятие — `/goal clear`.
- Контракт завершения — пять полей: `outcome`, `verification`, `constraints`, `boundaries`, `stop_when`. Чистовой промпт формируется через `writing-for-agents` и вставляется пользователем как есть (или через `/goal draft <текст>`).
- `/goal` в сессию оркестратора ставить не стоит для большой кампании без нужды: судья будет гонять именно оркестратора; канбан-карты с `--goal` изолируют луп в воркере.

## Канбан --goal: проверенные факты

- Флаг на `hermes kanban create --goal` + `--goal-max-turns <n>` (у `kanban_show`/диспетчера — `goal_mode`); судья сверяет последний ответ воркера с телом карты и продолжает до выполнения критериев или бюджета.
- Родители карт (`parents=[...]`) повторяют граф блокировок тикетов — диспетчер продвигает фронт сам.
- Воркер безголовый: спросить пользователя не может, поэтому коммит/пуш/деплой остаются вне лупа; приёмка диффа — за оркестратором или ревьюером карты.
- Дефолтная модель воркера — пин профиля; писатель внутри воркера (например, Cursor) — отдельный пин по `cli-agent-first`.

## Шаблон промпта кампании для /goal (структура)

1. Исход: фронтир и граф, рабочее дерево (абсолютный путь), трекер и переменные окружения для `gh`.
2. Контур тикета: клейм → бриф-файл → писатель → приёмка (свой прогон) → закрытие пруфом. Для каждого шага — критерий «готово когда».
3. Инварианты: авторитет тела тикета и спеки, один писатель на дерево, внешние мутации только по слову владельца, секреты вне чтения.
4. Стоп-условие: все тикеты закрыты с пруфом и финальный ревью зелёный, либо честный блокер с точным описанием.

## Когда что брать

- Нужен живой контроль между тикетами, ответы пользователю по ходу, коммиты по явному слову — ручной контур.
- Пользователь хочет «поставил и ушёл» в этой же сессии — `/goal` с контрактом; предупредить про бюджет и `/goal resume`.
- Кампания длинная и должна пережить сессии — канбан-карты `--goal` по тикетам с родителями по графу.
