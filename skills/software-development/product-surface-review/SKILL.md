# Product Surface Review

Один процесс: _brief_ → _inventory_ → _identity_ → _access_ → _side effects_ → _corpus honesty_ → _вердикт_.

Не launch-gates (`launch-readiness-review`) и не тикетный IMPLEMENTED (`spec-checklist-audit`). Вопрос: что человек увидит и совпадает ли это с заявленным продуктом.

Сними live git: ветка, dirty, origin, worktrees. Задачи и хаб — `project-briefing`; хаб не live HEAD.

## Когда

Просят ревью поверхностей, «чё как / чё не так», что увидит ученик или админ, identity AI-копии, Telegram vs web vs Studio. Параллельный ingest не повод деплоить и не повод его чинить в этом ходе.

Готово: назван класс работы — поверхности, не CI и не corpus pipeline.

## Границы

Read-only. Не commit, push, merge, deploy, polling и не правь чужой ingest.

Живой пайплайн, который ты не запускал, только опиши (ready / failed / running и чем валится). Чужой lock — строка в «Ждёт», не инцидент этой сессии.

Публичный HTTP из сессии может не пройти. Тогда: домен есть в конфиге, live fetch не проверен. Не объявляй хост мёртвым.

Готово: мутаций нет; каждый блокер помечен как код / контент / доступ / внешний lock.

## Inventory

Собери поверхности из routes и команд, не из README:

- вход (login / deny / grant);
- основной канал (часто Telegram);
- второй канал (web chat);
- шаринг / снимок / public token;
- Studio / admin;
- API, если им пользуется человек или другой канал.

На каждую: маршрут, обещание (спека / `CONTEXT.md` / оффер), фактический копирайт, кто проходит, побочный эффект на показ.

Таблица в ответе. Пустая поверхность — «нет в коде», не «не смотрел».

Готово: полный список из кода.

## Identity

Три слоя, все три:

1. Канон — `CONTEXT.md`, спека, шапка UI.
2. Runtime — `runtime.json`, system/style/answer prompts, `/start` `/about` `/help`.
3. Хром канала — заголовки, кнопки, дисклеймеры, пустые плейсхолдеры контакта.

Расхождение слоёв — главный дефект даже при зелёном CI. Если канон говорит «AI-копия / характерная речь», а style запрещает имитацию, продукт отрицает себя на главной поверхности.

Пустой contact handle и вечный «я не он» на `/start` — identity, не мелочь.

Готово: каждый слой процитирован; противоречие названо без сглаживания.

## Access и side effects

Кто видит поверхность ≠ кто может мутировать.

Проверь: Studio URL в шапке ученика; `requireStudio == requireChat`; кнопка, которая публикует снэпшот при рендере ответа, а не по нажатию; voice/vision в acceptance при выключенных флагах.

Обещание кнопки и момент side effect должны совпадать. Иначе — дефект поверхности, не «обогащение доставки».

Готово: каждая дыра доступа или eager-publish названа с путём.

## Честность корпуса

Не сливай в одно: каталог, файлы на диске, ingest jobs, опубликованный индекс, skill cards.

Каталог `not_loaded` при живых транскриптах — честный каталог и, часто, лживый хаб. Назови оба.

Пустой skill pack при «отвечаю как эксперт» — продукт ещё не эксперт, сколько бы уроков ни качалось.

Готово: четыре счётчика раздельно, без «материалы уже есть».

## Вердикт

```text
Поверхности: <список>
Врёт: <identity / access / side effect — по убыванию урона>
Уже держится: <единство ядра, реестр, fail-closed>
Не сейчас: <ingest, сервер, live GO — если это не поверхность>
Следующий шаг: <одно, обычно копирайт или доступ, не деплой>
```

Код release-ready не отменяет враньё `/start`. Заливать корпус в продукт, который отказывается звучать как обещанный эксперт — пропуск.
